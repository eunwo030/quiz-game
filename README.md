# 🎯 나만의 파이썬 콘솔 퀴즈 게임 (quiz-game)

본 프로젝트는 파이썬 기본 문법, 객체 지향 프로그래밍(OOP), 파일 입출력(JSON), 그리고 Git/GitHub 워크플로우를 학습하고 실습하기 위해 제작된 콘솔 기반 퀴즈 게임 프로그램입니다.

---

## 📌 1. 퀴즈 주제 및 선정 이유
- **주제:** 배은우 맞춤형 인물 퀴즈 및 파이썬 기초 퀴즈
- **선정 이유:** 프로그래밍의 기초 개념(자료형, 조건문, 함수 등)과 사용자 지정 데이터 간의 흐름을 직관적으로 확인하고 재미있게 테스트하기 위해 선정했습니다.

---

## 🚀 2. 실행 방법

1. 저장소를 클론(Clone)합니다.
git clone [https://github.com/eunwo030/quiz-game.git](https://github.com/eunwo030/quiz-game.git)
cd quiz-game

2. 파이썬 프로그램을 실행합니다. (Python 3.10 이상 권장)
python main.py

---

## 🛠️ 3. 주요 기능 목록

- 🎯 1. 퀴즈 풀기: 저장된 퀴즈가 순서대로 출제되며 정답 입력 시 점수를 집계합니다. 최고 점수 달성 시 갱신 및 파일 저장됩니다.
- 📌 2. 퀴즈 추가: 문제, 4개 선택지, 정답 번호를 직접 받아 새로운 퀴즈를 등록합니다.
- 📋 3. 퀴즈 목록: 현재 등록되어 있는 퀴즈 문제들의 목록을 한눈에 확인할 수 있습니다.
- 🏆 4. 최고 점수 확인: 역대 퀴즈 풀기에서 달성한 최고 점수를 보여줍니다.
- ⚠️ 5. 예외 처리: 
  - 잘못된 숫자/문자/빈 칸 입력 시 안내 메시지 출력 후 재입력 유도
  - Ctrl+C 또는 입력 종료 시 비정상 종료 방지 및 안전한 데이터 저장
  - 데이터 파일 손상/부재 시 기본 데이터 복구 로직 포함

---

## 📁 4. 프로젝트 파일 구조

- main.py : 퀴즈 게임 메인 실행 파일 (Quiz, QuizGame 클래스)
- state.json : 퀴즈 데이터 및 최고 점수가 저장되는 JSON 파일
- .gitignore : Git 추적 제외 파일 목록
- README.md : 프로젝트 설명 문서

---

## 📂 5. 데이터 파일 설명 (state.json)

- 경로: 프로젝트 루트 디렉터리 ./state.json
- 역할: 프로그램 종료 후에도 추가한 퀴즈와 최고 점수가 유지되도록 UTF-8 인코딩으로 저장
- 데이터 스키마 예시:
{
    "quizzes": [
        {
            "question": "배은우가 사는 지역은?",
            "choices": ["서울", "부산", "대전", "광주"],
            "answer": 3
        }
    ],
    "best_score": 5

}---

## 🏗️ 6. 클래스 설계 및 역할 분리 (#8, #13, #20)
- **`Quiz` 클래스:** 개별 퀴즈 데이터(`question`, `choices`, `answer`)와 문제 출력(`display`), 정답 판정(`is_correct`), 딕셔너리 변환(`to_dict`, `from_dict`) 책임을 가집니다.
- **`QuizGame` 클래스:** 퀴즈 목록 및 최고 점수 상태 관리, 메뉴 출력 및 입력 검증(`get_valid_input`), 게임 진행(`play_quiz`, `add_quiz`, `show_quizzes`, `show_best_score`), `state.json` 저장/불러오기(`save_data`, `load_data`)를 담당합니다.
- **클래스(OOP)를 선택한 이유:** 퀴즈 데이터와 게임 상태·로직을 객체 단위로 묶어 관리하면 코드 재사용성과 유지보수성이 높아집니다. 단순 함수형 구조만 쓰면 전역 변수와 상태 흐름이 얽혀 기능이 커질수록 추적이 어려워집니다.
- **요구사항 변경 시 수정 대상 메서드:**
  - 입력 규칙/범위 변경: `get_valid_input`, `add_quiz`, `play_quiz`
  - 저장 형식/경로/복구 정책 변경: `load_data`, `save_data`, `init_default_quizzes`
  - 메뉴/게임 흐름 변경: `display_menu`, `run`, `show_quizzes`, `show_best_score`

## 🌿 7. Git 워크플로우 및 커밋 규칙 (#12, #16)
- **브랜치 전략:** `main` 브랜치는 안정적인 기준 상태로 유지하고, 새 기능이나 수정 사항은 별도 브랜치(예: `feature/quiz-logic`)에서 작업한 뒤 `main`으로 병합(`merge`)해 변경 이력을 안전하게 통합합니다.
- **커밋 메시지 규칙:** `<유형>: <간단한 설명>` 형식을 사용합니다.
  - 유형 예시: `Feat`(기능 추가), `Fix`(오류 수정), `Docs`(문서 수정), `Chore`(설정/기타)
  - 예시: `Feat: 퀴즈 풀기 기능 구현`, `Fix: 잘못된 숫자 입력 예외 처리`

---

## 💾 8. 저장 방식 한계 및 백업·복구 안내 (#18, #19)
- **JSON 저장 방식의 한계:** `state.json` 전체를 한 번에 읽고 쓰는 방식이라 퀴즈 데이터가 매우 커지거나 동시 접근이 많아지면 파일 크기 증가에 따른 입출력 시간 및 메모리 부담이 커질 수 있습니다.
- **손상 시 백업 및 복구 안내:** `state.json` 파싱/읽기 오류가 발생하면 손상된 파일을 `state.json.bak`으로 백업한 뒤 기본 퀴즈 데이터로 초기화·복구하도록 안내합니다(복구/초기화 여부 확인 후 진행).
